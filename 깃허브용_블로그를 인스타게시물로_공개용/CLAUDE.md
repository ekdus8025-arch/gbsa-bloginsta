# <상호> 블로그 → 인스타그램 게시물 변환 프로젝트

## 1. 프로젝트 목적
<상호> 블로그 글 1편을 인스타그램 캐러셀 게시물 1개(슬라이드 원고 + 캡션 + 해시태그)로 바꾼다.
- 현재 범위: **텍스트만** 만든다. 이미지 생성, 이미지 프롬프트, Canva 작업은 하지 않는다.
- 결과물은 사람이 검토한 뒤 직접 업로드한다. 자동 발행은 하지 않는다.

## 2. 폴더 구조
```
<상호>-insta/
├── CLAUDE.md          이 파일 (업무 지시서)
├── rules/             세부 규칙 — 작업 단계마다 해당 파일을 반드시 먼저 읽는다
│   ├── 00_brand.md        브랜드 정보, 타깃, 연락처, 표기 규칙
│   ├── 01_structure.md    캐러셀 구성, 장수, 슬라이드 종류, 장당 글자 수
│   ├── 02_tone.md         문체, 말투, 금지 표현
│   ├── 03_caption.md      캡션 구조, CTA, 해시태그
│   └── 04_checklist.md    검수 체크리스트
├── templates/         결과물 양식 — 항목과 순서를 바꾸지 않는다
│   ├── slides_template.md
│   └── caption_template.md
├── examples/          모범 답안 (있으면 수준과 형식을 참고)
├── input/             블로그 원문 (읽기 전용)
└── output/            완성본 (글 1편당 폴더 1개)
```

## 3. 작업 순서
사용자가 "변환해 줘" 또는 파일명을 주면 아래 4단계를 순서대로 진행한다.
단계마다 결과를 파일로 저장하고, 앞 단계 파일을 근거로 다음 단계를 만든다.
`rules/03_caption.md`는 규칙 파일이고, `output/` 안의 `03_caption_post.md`는 결과 파일이다. 둘을 헷갈리지 않는다.

### 1단계: 분석 → `01_analysis.md`
- 읽을 파일: `input/`의 원문, `rules/00_brand.md`
- 정리할 것: 글의 핵심 주제 한 줄, 타깃, 핵심 정보 5~8개, 원문에 나온 숫자(가격·기간·거리·시간)와 그 출처 문장
- 원문만으로 판단이 어려운 부분은 "확인 필요"로 표시한다.

### 2단계: 슬라이드 원고 → `02_slides.md`
- 읽을 파일: `01_analysis.md`, `rules/01_structure.md`, `rules/02_tone.md`, `templates/slides_template.md`
- 템플릿의 필드명(`cover_title`, `info1_title` 등)을 그대로 쓴다. 나중에 Canva 자동 채우기와 연결한다.

### 3단계: 캡션·해시태그 → `03_caption_post.md`
- 읽을 파일: `02_slides.md`, `rules/03_caption.md`, `rules/02_tone.md`, `templates/caption_template.md`

### 4단계: 검수 → `04_review.md`
- 읽을 파일: `rules/04_checklist.md`, `input/` 원문, `02_slides.md`, `03_caption_post.md`
- 체크리스트 항목마다 통과/수정 필요를 적는다.
- 수정이 필요한 항목은 바로 고치고, 무엇을 어떻게 고쳤는지 기록한다.

## 4. 파일 이름 규칙
- 원문: `input/YYYY-MM-DD_주제-영문.md` (예: `2026-11-25_dubai-family-cost.md`)
- 결과 폴더: `output/`에 원문 파일명과 같은 이름으로 만든다.
- 폴더·파일 이름은 영어 소문자, 숫자, 하이픈(-), 밑줄(_)만 쓴다. 날짜와 주제 사이는 밑줄, 주제 단어 사이는 하이픈으로 잇는다. 내용은 한국어로 쓴다.

## 5. 절대 규칙
1. **원문에 없는 정보를 만들지 않는다.** 가격, 일정, 포함 사항, 운영 시간, 통계는 원문에 있는 것만 쓴다.
   예외: `rules/` 파일에 정해 둔 고정 문구(CTA, 브랜드 표기, 가격 변동 안내)는 원문에 없어도 쓴다.
2. **숫자는 원문 그대로 쓴다.** 반올림하거나 "약", "최저" 같은 말을 붙여 의미를 바꾸지 않는다.
3. **상담 사례, 고객 후기, 개인 경험담을 지어내지 않는다.** <상호>는 아직 쌓인 고객 후기가 없다.
4. **과장·긴급성 문구를 쓰지 않는다.** (예: 마감 임박, 최저가 보장, 지금 아니면 끝)
5. `input/` 원문 파일은 수정하거나 삭제하지 않는다.
6. 이미 있는 `output/` 폴더를 덮어써야 할 때는 먼저 사용자에게 묻는다.
7. 규칙 파일끼리 내용이 충돌하면 임의로 고르지 말고 사용자에게 알린다.

## 6. 사용자에게 먼저 물어볼 때
- `input/`에 원문이 없거나 여러 개라서 어떤 글인지 모를 때
- 원문에 가격·일정 정보가 없어서 핵심 슬라이드를 채우기 어려울 때
- `rules/` 파일이 비어 있거나 없을 때 (없는 규칙을 짐작해서 채우지 않는다)

## 7. 완료 보고 형식
4단계가 끝나면 아래처럼 짧게 보고한다.
```
✅ 변환 완료: output/<폴더명>/
- 슬라이드: N장
- 검수: 통과 N개 / 수정 N개
- 확인 필요: (원문 대조가 필요한 항목, 없으면 "없음")
```
