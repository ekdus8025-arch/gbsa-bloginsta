# 01_structure.md — 캐러셀 구성 규칙

> 블로그 글 1편을 인스타그램 캐러셀 1개로 바꿀 때 슬라이드를 어떻게 구성하는지 정한다.
> 문체는 `rules/02_tone.md`, 캡션 규칙은 `rules/03_caption.md`, 브랜드 정보는 `rules/00_brand.md`를 따른다.
> 현재 범위는 텍스트만이다. 사진 칸(`cover_photo`, `infoN_photo`)은 이름만 남기고 내용은 비워 둔다.

## 1. 기본 규격
| 항목 | 규칙 |
|---|---|
| 크기 | 1080×1350 (4:5 세로) |
| 장수 | 7~9장 (기본 8장). 6장 이하, 10장 이상은 쓰지 않는다 |
| 한 장의 메시지 | 1장 = 1메시지. 두 가지를 말하고 싶으면 장을 나눈다 |
| 줄 수 | 본문은 한 장에 최대 3줄 |
| 한 줄 길이 | 공백 포함 18자 안팎 (휴대폰에서 줄바꿈 없이 읽히는 길이) |
| 숫자 | 원문 숫자 그대로. 단위(원, 일, 시간, km)를 꼭 붙인다 |
| 줄바꿈 표시 | 원고에서 한 필드 안의 줄바꿈은 ` / `로 쓴다 (예: `아이랑 두바이 / 비용 이만큼 들어요`) |

## 2. 슬라이드 6종

### S1. 표지 (cover) — 필수, 1장, 항상 1번
- **역할**: 피드에서 멈추게 하고 넘기게 만든다.
- **필드**
  | 필드명 | 내용 | 글자 수 |
  |---|---|---|
  | `region_tag` | 지역 영문 대문자 (예: DUBAI, CROATIA) | 12자 이내 |
  | `cover_title` | 후킹 제목 | 2줄, 줄당 12자 이내 |
  | `cover_sub` | 보조 설명 한 줄 | 25자 이내 |
  | `cover_photo` | (비워 둠) | — |
- **규칙**
  - 제목에는 구체적인 대상이나 숫자를 넣는다. 숫자는 원문에 있는 것만 쓴다. (예: "아이랑 두바이 5일", "발칸 3개국 핵심 동선")
  - 질문형, 숫자형, 비교형 중 하나로 쓴다. 질문형은 S1·S2 중 한 곳에만 쓴다 (`02_tone.md` 2). 표지가 질문형이면 S2는 공감 문장으로 쓴다.
  - 콤마(,)와 세로바(|)를 쓰지 않는다.
- ✅ 좋은 예: `아이랑 두바이 / 비용 이만큼 들어요`
- ❌ 나쁜 예: `두바이 여행 총정리` (무엇을 얻는지 안 보임)

### S2. 공감·문제 제기 (hook) — 필수, 1장, 항상 2번
- **역할**: "내 얘기네" 하고 계속 넘기게 만든다.
- **필드**: `hook_text` (2줄, 줄당 18자 이내)
- **규칙**
  - 타깃이 실제로 하는 고민을 한 문장으로 쓴다.
  - 원문에 고민이나 질문이 나오면 그 내용을 쓴다. 없으면 글의 주제에서 자연스럽게 나오는 고민만 쓴다.
  - 고객 사례처럼 쓰지 않는다. ("상담 오신 고객님이…" 금지)
- ✅ 좋은 예: `동유럽이랑 발칸 / 같이 가도 일정이 괜찮을까요?`

### S3. 정보형 A — 사진 + 설명 (info) — 선택, 0~4장
- **역할**: 명소, 호텔, 체험, 음식 등 하나씩 소개한다.
- **필드** (N은 1부터 순서대로)
  | 필드명 | 내용 | 글자 수 |
  |---|---|---|
  | `infoN_title` | 대상 이름 또는 한 줄 핵심 | 15자 이내 |
  | `infoN_body` | 설명 | 최대 3줄, 줄당 18자 안팎 |
  | `infoN_photo` | (비워 둠) | — |
- **규칙**: 원문에서 소개한 대상만 쓴다. 원문에 없는 명소를 추가하지 않는다.

### S4. 정보형 B — 리스트·표 (list) — 선택, 0~2장
- **역할**: 비용, 일정, 준비물처럼 여러 항목을 한눈에 보여 준다.
- **필드**
  | 필드명 | 내용 | 글자 수 |
  |---|---|---|
  | `listN_title` | 리스트 제목 (예: "4인 가족 예상 비용") | 15자 이내 |
  | `listN_items` | 항목 3~5개, 한 줄에 하나 | 항목당 20자 이내 |
  | `listN_note` | 기준·조건 한 줄 (예: "2026년 1월 출발 기준") | 25자 이내, 원문에 있을 때만 |
- **규칙**
  - 가격·일정은 원문 그대로 옮기고, 원문에 적힌 기준(출발일, 인원, 포함 사항)이 있으면 `listN_note`에 쓴다.
  - 원문에 기준이 없는 가격은 쓰지 않고 `01_analysis.md`에 "확인 필요"로 남긴다.

### S5. 꿀팁·요약 (tip) — 필수, 1장, CTA 바로 앞
- **역할**: 저장하고 싶게 만든다.
- **필드**
  | 필드명 | 내용 | 글자 수 |
  |---|---|---|
  | `tip_title` | 요약 제목 (예: "이것만 기억하세요") | 12자 이내 |
  | `tip_items` | 핵심 3가지, ✔️로 시작 | 항목당 20자 이내 |
- **규칙**: 앞 슬라이드 내용을 다시 정리한다. 새로운 정보를 여기서 처음 꺼내지 않는다.

### S6. 상담 안내 (cta) — 필수, 1장, 항상 마지막
- **역할**: 상담과 프로필 방문으로 이어지게 한다.
- **필드**
  | 필드명 | 내용 |
  |---|---|
  | `cta_text` | 권유형 한두 줄 (예: "우리 가족 일정, 편하게 물어보세요") |
  | `cta_contact` | `00_brand.md` 6번 CTA 기본 문구 중 선택 |
  | `brand_line` | <브랜드 표기> · <대표 경력> |
- **규칙**: 연락처와 채널은 `00_brand.md`의 값만 쓴다. 재촉하는 표현을 쓰지 않는다.

## 3. 조립 순서
```
S1 표지 → S2 공감 → [S3 / S4 정보 슬라이드 4~6장] → S5 꿀팁 → S6 상담 안내
```
- 필수 4장(S1, S2, S5, S6) + 정보 슬라이드 3~5장 = 총 7~9장
- 정보 슬라이드는 원문 흐름 순서를 따른다.
- S4(리스트·표)는 연속 2장까지만 붙인다. 사이에 S3를 넣어 리듬을 바꾼다.

## 4. 글 유형별 기본 조합
| 블로그 글 유형 | 정보 슬라이드 조합 | 예시 |
|---|---|---|
| 비용 정리형 | S3 ×2 + S4 ×2 (비용표, 아끼는 법) | 두바이 가족여행 비용 |
| 일정·동선형 | S4 ×1 (전체 일정) + S3 ×3 (일자별 핵심) | 동유럽·발칸 9일 동선 |
| 명소 소개형 | S3 ×4 + S4 ×1 (가는 법·운영 정보) | 크로아티아 꼭 가야 할 곳 |
| 준비물·팁형 | S4 ×2 + S3 ×2 | 두바이 여행 준비물 |
| 상품 소개형 | S3 ×2 (포인트) + S4 ×2 (일정, 포함·불포함) | 발칸 패키지 상품 |

유형이 애매하면 `01_analysis.md`에 어떤 유형으로 판단했는지 이유와 함께 적는다.

## 5. 원문 → 슬라이드 옮기기 원칙
1. **고르기**: 원문의 핵심 정보 중 타깃에게 가장 쓸모 있는 것만 고른다. 전부 옮기지 않는다.
2. **압축하기**: 원문 문단을 그대로 붙이지 않는다. 한 장 3줄 안에 들어가게 줄인다.
3. **지키기**: 숫자, 고유명사(지명·호텔명·항공사), 조건은 원문 그대로 쓴다.
4. **남기기**: 슬라이드에 넣지 못한 중요한 정보는 캡션(결과 파일 `03_caption_post.md`)으로 보낸다.
5. **표시하기**: 슬라이드마다 원문의 어느 부분에서 가져왔는지 `02_slides.md`에 `출처:` 한 줄로 적는다. (검수용, 게시물에는 나가지 않음)

## 6. 공통 표시 요소 (디자인 단계에서 사용)
- 페이지 번호 `N/전체`를 모든 장에 넣는다.
- "넘겨보기 →" 표시는 S1, S2에만 넣는다.
- 계정명 `@<인스타 계정>`은 모든 장 같은 위치에 넣는다.
- 위 요소는 템플릿에 고정되므로 원고 필드에는 쓰지 않는다.
